# 独立手作创作者订单管理系统 (Handcraft Order Management System)

> 单一 APP 端小型信息系统 ｜ 面向独立手作创作者（手工饰品/皮具/烘焙/陶艺/编织）｜ 四类角色 ｜ 课程周期 8 周

一套把"接单 → 排期 → 制作 → 交付 → 算账"收进一个 APP 的轻量化订单管理系统。创作者不再依赖「微信私聊 + Excel + 手写笔记」三件套。

## 核心要解决的问题

| 痛点 | 本系统解法 |
|---|---|
| 订单散落微信/本子/Excel，易漏单错单 | 统一订单模块，固定状态机流转（待确认→制作中→待发货→已完成） |
| 算不清每单利润 | 成本 = 材料成本 + 工时成本，利润自动核算 |
| 库存与订单脱节、采购滞后导致交期延误 | 材料出入库 + 低库存预警 |
| 定制需求多变、进度同步靠人工回复 | 客户角色在线追踪进度、提交定制需求 |
| 商用系统功能冗余、收费高 | 单 APP + 四角色权限隔离的轻量化方案 |

## 系统架构

```
┌─ Qt C++ 移动端 APP（qt-app/）────────────────┐  界面交互、本地页面逻辑
│  创作者 / 客户 / 管理员 / 财务查看者（按角色登录）│
└────────────────────┬─────────────────────────┘
                     │ HTTP + JSON
┌────────────────────▼─────────────────────────┐
│ Java 业务接口层 REST API（java-backend/）       │  权限校验、订单状态流转、CRUD、非法数据拦截
└──────┬───────────────────────────┬───────────┘
       │ 进程调用 (ProcessBuilder)   │ 进程调用
┌──────▼──────────┐      ┌─────────▼─────────┐  ┌──────────────────┐
│ python/order_   │      │ python/analytics  │  │ MySQL 8.0        │
│ classifier.py   │      │ .py 数据分析模块   │  │ （sql/schema.sql）│
│ 智能订单分类(规则)│      │ 经营画像/报表      │  └──────────────────┘
└─────────────────┘      └───────────────────┘
```

> 设计决策：Python 模块以**本地脚本**形式运行，由 Java 通过 `ProcessBuilder` 进程调用（不走 HTTP，避免"本地脚本还要起服务"的架构矛盾），脚本直连业务数据库读取/写回结果。

## 功能模块与优先级（P0 为演示保底闭环）

| 优先级 | 创作者 | 客户 | 管理员 | 财务查看者 |
|---|---|---|---|---|
| P0 | 订单管理、材料库存、成本利润 | — | 用户管理、角色权限 | 数据统计、财务报表 |
| P1 | 排期日历、客户管理 | 订单追踪/详情/定制提交 | 基础数据配置 | 财务统计 |
| P2(视进度) | — | 定制提交完善 | 公告管理(简化) | 报表导出 |

**P0 主链路**：创作者建单/客户提交定制 → 智能分类模块识别类型并算预估工期 → 生成订单+更新排期 → 创作者推进状态 → 客户实时可见 → 完成时结算成本利润并刷新经营报表。

## 两大创新点（轻量化，非大模型）

1. **智能订单分类与工期提醒**：关键词-规则匹配。含「定制/专属/个性化/按需」→ 定制类；「现货/现款/成品」→ 现货类；「批量/团购/多件」→ 批量类；未命中兜底"通用类"由创作者手动调整。按类型+数量算预估工期，截止日前 3 天提醒。
2. **数据统计分析（经营画像）**：利润趋势（月/季）、客户复购率与客单价分布、材料消耗分析、客户价值分层。
