# 04 数据库设计文档 —— handcraft_order (MySQL 8.0)

> 设计原则：三范式；InnoDB；utf8mb4_unicode_ci；外键 RESTRICT；建库脚本 `sql/schema.sql`。

## 1. 实体关系总览（详见 docs/diagrams/er-diagram.svg）
role 1─N user N─1 customer；customer 1─N orders；orders N─1 product_category；
material_category 1─N material 1─N stock_movement & order_material(N─1 orders)；
orders 1─N order_status_log；user 1─N announcement(publisher)。

## 2. 表清单（11 张）
| 表 | 说明 | 关键约束 |
|---|---|---|
| role | 角色(4类) | role_code 唯一 |
| user | 登录账号(密码 BCrypt) | username 唯一；role_id FK；customer_id FK(循环外键后置 ALTER) |
| customer | 客户档案 | creator_id FK(归属创作者) |
| product_category / material_category | 基础数据分类 | name 唯一 |
| material | 材料主档(库存量+阈值+单价) | stock_qty/阈值 decimal |
| stock_movement | 出入库流水(单表双方向) | direction IN/OUT；order_id 可空 |
| orders | 订单(核心) | order_no 唯一；order_type/status 枚举；CHECK quantity≥1 |
| order_status_log | 状态审计 | 每次流转一行 |
| order_material | 订单耗料明细 | quantity_used/unit_cost 快照 |
| announcement | 公告(P2 简化) | status 1发布/0下线 |

## 3. orders 核心字段
order_no(HC+时间戳+随机3位)、customer_id、creator_id、product_name、requirement、
order_type(CUSTOM/READY/BATCH/GENERAL)、quantity、unit_price、
material_cost、labor_cost(录入)、status(PENDING_CONFIRM/IN_PRODUCTION/PENDING_SHIPMENT/COMPLETED/CANCELLED/ARCHIVED)、
estimate_days、estimated_complete_date、actual_complete_date、source(MANUAL/CUSTOMER)、remark、created_at/updated_at。

## 4. 视图（3 个）
| 视图 | 用途 |
|---|---|
| v_order_profit | 经营统计行(收入/总成本/利润)，仅 COMPLETED 或(ARCHIVED 且 actual_complete_date 非空) |
| v_low_stock | 低库存预警(stock_qty ≤ low_stock_threshold) |
| v_due_reminder | 工期提醒(截止 ≤ 今天+3 天含超期，未完结，含 creator_id 供隔离) |

## 5. 触发器（1 个）
`trg_stock_movement_in`(AFTER INSERT ON stock_movement)：IN 累加、OUT 扣减 material.stock_qty —— 库存唯一写入口，保证流水与库存一致。

## 6. 一致性设计
- 库存永不手改：只通过 stock_movement 插入触发变更。
- 材料成本冗余于 orders.material_cost，由服务端在耗料登记后按 Σ 回写（读快、口径唯一）。
- 取消/完成不物理删除订单：状态流转 + 审计日志，满足"防漏单/错单可追溯"。
- 循环外键(user↔customer)：先建表后 `ALTER TABLE user ADD CONSTRAINT fk_user_customer`。
